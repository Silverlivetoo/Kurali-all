================================================================================
KuraliAll 用户反馈问题及修复总结
================================================================================

反馈日期: 2026-03-28
项目版本: v2.2.0

================================================================================
一、用户反馈的问题
================================================================================

【问题1】桌面图标缺失
  - 描述: 安装完 app 后没有桌面图标，也没有启动菜单里的图标
  - 影响: 用户无法通过图形界面启动已安装的软件

【问题2】RAM 运行模式体验差
  - 描述: kurali run xx.xx 的时候根本不知道 app 运行在哪里
  - 影响: 用户无法找到运行中的程序窗口

【问题3】无法关闭运行中的程序
  - 描述: 不知道怎么关闭 app
  - 影响: 用户不知道如何终止已启动的程序

【问题4】.kurali 打包问题
  - 描述: 打包完 .kurali 格式后还要安装这个 app，打包出来的 .kurali 文件里啥也没有
  - 影响: 打包功能形同虚设，无法实现"打包后直接运行"

【问题5】WebUI 版本无法使用
  - 描述: webui 版本根本没办法用
  - 影响: Web 界面无法正常工作

【问题6】GUI 模式功能失效
  - 描述: gui 模式好多功能实际上不能用，安装 app 的时候一点就提示安装成功但实际上啥用没有
  - 影响: 终端 GUI 界面点击安装后实际未安装

【问题7】键盘交互逻辑混乱
  - 描述: 有时候键盘交互还逻辑混乱
  - 影响: 用户体验差，操作不直观

================================================================================
二、已完成的修复
================================================================================

【修复1】桌面图标问题 (Shell版 + Python版 + WebUI版)
  - 修复内容: 即使没有找到图标文件，也创建 .desktop 启动器，使用系统默认图标
  - 修改文件:
    * kuraliAll.sh
    * modules/desktop.mod
    * kuraliAll.py (新增 install_desktop_entry_py / remove_desktop_entry_py 函数)
    * kuraliAll-webui.py

【修复2】RAM 运行体验
  - 修复内容: 运行程序时显示 PID，并提示如何关闭
  - 显示信息:
    * ✓ 进程已启动 (PID: 12345)
    * 关闭方式: kill 12345 或 pkill -f 'appname'
    * 提醒: 关闭后 RAM 中的数据会被清除
  - 修改文件: kuraliAll.py

【修复3】.kurali 打包功能
  - 修复内容:
    * 添加打包结果验证，确保 .kurali 文件包含有效内容
    * 显示直接运行命令: kurali --ram xxx.kurali (不需要先安装)
    * 修复版本提取: 从 deb/rpm 等格式正确提取版本号
  - 修改文件:
    * modules/pkg-handler.mod
    * kuraliAll.py

【修复4】WebUI 修复
  - 修复内容:
    * 数据目录路径: 自动检测操作系统，Windows 使用用户目录，Linux 使用 /var/lib/kuraliAll
    * 依赖检查逻辑: 修复 lib.replace('.so','') 错误，改为前缀匹配
    * 桌面图标集成: WebUI 安装时自动创建 .desktop 启动器
  - 修改文件: kuraliAll-webui.py

【修复5】GUI 模式修复
  - 修复内容:
    * 数据目录路径: 自动检测操作系统，Windows 使用用户目录
    * 安装功能: 修复调用错误，调用 kuraliAll.py 而不是自身
    * 卸载功能: 同样修复调用错误
    * RAM 模式: 同样修复调用错误
    * list 功能: 实现了显示已安装列表功能
    * CLI 跳转: 使用 os.execv 正确跳转到 kuraliAll.py
  - 修改文件: kuraliAll-gui.py

四、注意事项
================================================================================

1. 所有版本(Shell/Python/WebUI/GUI)仍需要在 Linux 环境下运行，因为依赖
   dpkg-deb、rpm、cpio 等 Linux 命令行工具。

2. Windows 环境下数据目录会自动切换到用户目录，但核心安装功能仍需要 Linux。
