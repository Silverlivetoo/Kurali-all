# 2026-03-28

## 查看项目代码
- 项目：KuraliAll v2.2.0，全能 Linux 包管理器
- 包含4个版本：kuraliAll.sh（Shell）、kuraliAll.py（Python）、kuraliAll-gui.py（curses GUI）、kuraliAll-webui.py（WebUI）
- 支持格式：.deb .rpm .pkg.tar.* .apk(Alpine) .kurali .AppImage .tar.* .zip
- 模块化架构：modules/ 目录下有 core.mod / pkg-handler.mod / ram-run.mod / docker-run.mod / desktop.mod / service.mod

## Bug 修复（全项目）
修复了以下 Bug：

### kuraliAll.py
1. `cmd_run()` finally 块残留 `debug_cleanup = True` 无用变量
2. `cmd_remove()` 符号链接路径错误：`Path.home()/"local/bin"` → `Path.home()/".local/bin"`
3. `extract_package()` deb 的 `ar x` 传入未转 str 的 Path 对象
4. deb 版本提取时 `r.returncode` 在 `r=None` 时崩溃，增加 None 判断
5. `cmd_deps()` ldconfig 匹配逻辑错误（`lib.replace('.so','')` 改为 `lib.split('.')[0]`）
6. apk 包名/版本提取改用 `getmember()` 更安全，传入 `str(filepath)` 
7. `cmd_pack()` manifest.json 用 `json.dumps` 代替手动字符串拼接
8. HELP 和 docstring 版本号统一为 v2.2.0
9. extract_package 中 glob import 移至文件顶层

### modules/pkg-handler.mod
1. `detect_format()` tar 格式检测运算符优先级 Bug（`||` 和 `&&` 混用）
2. `pack_kurali()` 两次 `tar czf` 第二次覆盖第一次输出，改为一次性打包
3. `pack_kurali()` `sed -i` 修改 manifest.json 不可靠，改用 heredoc 重新生成完整 JSON

### modules/system.mod
1. `select_distro()` read 提示符括号未闭合：`[1-${idx}:` → `[1-${idx}]:`

### modules/core.mod
1. `danger_confirm()` read 提示符颜色转义未重置（缺少 `${C_RESET}`）
2. `show_help()` 版本号从 v2.1 修正为 v2.2.0

### modules/ram-run.mod
1. 用户输入非数字时 `-ge/-le` 比较报错，增加 `^[0-9]+$` 正则先验证

### kuraliAll.sh
1. `cmd_list()` 表头打印逻辑 Bug（两次 `entries -eq 0` 判断，应用独立 flag）
2. `--ram FILE` 快捷方式：FILE 被当作 cmd，修复为正确移入 args
3. 顶部注释版本号从 v2.1 修正为 v2.2.0

### kuraliAll-gui.py
1. docstring 版本号从 v2.1 修正为 v2.2.0
